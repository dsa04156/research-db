# 3. 장기 실행 에이전트의 운영 표면

## 검증된 핵심 주장

**clm_003 — 장시간 실행 에이전트의 운영 핵심은 최종 응답만 보는 것이 아니라
실행 궤적 관찰, 행동 회귀 테스트, 지속 메모리의 보안·삭제 검증을 함께
갖추는 것이다.**

AgentGUI는 여러 장기 세션의 실행 궤적을 시각화하고 사람이 개입하거나 자동으로
drift를 완화하는 인터페이스를 제안한다
([src_007](https://arxiv.org/abs/2607.26300)). MemSecBench는 장기
메모리에 악성 의미가 기록된 뒤 실제 행동으로 이어지고, 선택적으로 삭제되는
전체 수명주기를 검사한다
([src_008](https://arxiv.org/abs/2607.27080)). 행동 테스트는 응답 문자열뿐
아니라 어떤 도구를 어떤 인자로 호출했는지와 안전 정책을 검사한다
([src_006](https://developers.redhat.com/articles/2026/07/30/behavioral-testing-for-ai-agents)).

Agent OS 관점의 포지션 페이퍼도 현재 프레임워크가 난립하지만 이식 가능한
핵심 추상화와 보장 의미는 아직 정리되지 않았다고 진단한다
([src_017](https://arxiv.org/abs/2607.25076)). 따라서 지금은 특정
프레임워크 하나에 DB를 묶기보다 다음 공통 이벤트를 보존하는 편이 안전하다.

- 입력 컨텍스트와 출처
- 계획과 상태 전이
- 도구 이름·인자·결과
- 메모리 write/read/forget
- verifier 결과와 승인 주체
- 비용·지연·중단·재시도

이 이벤트 모델을 SQLite에 저장하면 나중에 프레임워크를 바꾸더라도 실패 분석,
행동 회귀 테스트, 하네스 진화 학습 데이터를 재사용할 수 있다.
