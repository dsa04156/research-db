## 지난 종합과 달라진 점

지난주는 workspace·sandbox·persistent state가 공통 제어면으로 묶이기 시작한 주였다. 이번 주는 그 제어면이 공개 하네스, SDK 테스트 API, 네트워크 차단, CNCF 졸업 프로젝트, GPU DRA처럼 구체적인 제품·운영 표준으로 내려왔다. 논점이 “하네스가 필요한가”에서 “하네스를 어떻게 검증하고 업그레이드할 것인가”로 이동했다.

## 분야별 핵심 변화

### Self-evolving harness

DeepSeek Harness가 모델·도구·세션·루프를 교체 가능한 구조로 공개됐다. Evo-Bench·DarwinX 등 하네스를 평가하거나 지속 개선하는 연구도 늘었지만 아직 초기 연구 비중이 높다.

### AI agents

OpenAI Agents SDK는 결정론적 테스트, 상태 격리, timeout, network-off, 승인 정확성과 사용량 집계를 강화했다. 에이전트 개발의 중심이 prompt 작성에서 실행 정책과 회귀 테스트로 이동한다.

### Kubernetes

Kubeflow 졸업은 AI/ML 수명주기 플랫폼의 거버넌스 성숙을 의미한다. DRA는 GPU 분할, 장치 건강, binding condition, workload 단위 자원 요청으로 확장되지만 기능 단계가 섞여 있어 점진 도입이 필요하다.

### Cloud·Distributed

자가복구 업그레이드와 LLM 기반 제어면 연구가 함께 나타났다. 자동 조치가 늘어날수록 rollback, quorum, tail latency, token budget을 함께 측정해야 한다.

### Edge AI

workerd는 GC 누수와 스트림 참조 수명을 수정했다. 온디바이스·저지연 논의는 계속되지만 이번 주에는 독립 검증된 큰 성능 전환보다 런타임 안정성 개선이 더 뚜렷했다.

## 분야를 가로지르는 연결

하네스 plugin, agent approval, Kubernetes ResourceClaim, edge runtime reference lifetime은 모두 “누가 어떤 자원을 얼마 동안 사용할 수 있는가”를 표현한다. AI 인프라의 공통 추상화는 모델 호출이 아니라 **권한과 자원의 수명주기**가 되고 있다.

## 합의가 형성된 주장

- 장기 실행 에이전트에는 결정론적 테스트와 실패 재현 경로가 필요하다. Confidence: High.
- sandbox는 network·filesystem·secret·approval을 각각 제한해야 한다. Confidence: High.
- Kubernetes AI 운영은 파이프라인 수명주기와 GPU 자원 관리가 함께 표준화돼야 한다. Confidence: High.
- 자동 복구는 성공률뿐 아니라 rollback·quorum·자원 누수를 측정해야 한다. Confidence: Medium-High.

## 서로 충돌하는 주장

- 공개 하네스의 빠른 커뮤니티 확산과 실제 프로덕션 안정성 사이에는 검증 간극이 있다.
- DRA는 GPU 운영의 방향으로 합의가 커지지만 일부 공유·분할 기능은 아직 alpha/beta 또는 기본 비활성이다.

## Kubernetes·Cloud·Edge 운영 영향

- agent 릴리스 게이트에 timeout, max-turn, network-off, approval replay를 넣는다.
- DRA 도입은 기존 device plugin과 병행하며 feature gate·driver·GPU 세대별 호환성을 검증한다.
- 장기 worker의 GC root, stream 종료, child provider 정리를 관측한다.
- 자동 업그레이드는 rollback과 상태 수렴을 먼저 설계한다.
- engagement와 제품 별점은 성능·비용 근거에서 제외한다.
