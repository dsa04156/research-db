## 지난 종합과 달라진 점

지난 종합이 durable runtime과 캐시 인지 라우팅의 필요성을 다뤘다면, 이번 주는 그것을 실제 운영 정책으로 내리는 변화가 두드러졌다. 비-root 노드, 세션 영속성, 소유자 단위 task 접근, 스캔 API 고가용성처럼 “어디까지 실행하고 어떻게 되돌릴지”가 릴리스 항목으로 나타났다.

## 분야별 변화

### Self-evolving harness

평가를 제품 일부로 다루고, 결함 유형·통제된 ablation·과정 증거를 남겨야 한다는 흐름이 강해졌다. Environment Evolution은 환경 난이도까지 학습 중 바꾸는 방향을 제안했지만 성능 수치는 독립 재현 전이다.

### AI agents

kagent는 sandbox runtime, 영속 세션, A2A task store, guardrail과 소유자 범위 접근제어를 확장했다. HydraFusion은 작업에 따라 여러 모델을 고르는 연구 프리뷰를 공개했지만 비용·품질 수치는 공급자 자체 평가다.

### Kubernetes

KubeletInUserNamespace가 베타가 됐다. 컨테이너 탈출 피해를 host root에서 분리하는 데 도움이 되지만 커널 취약점은 막지 못하고 일부 CNI·CSI 호환성 확인이 필요하다.

### Cloud·Distributed

Netflix의 Flink autoscaler 사례는 상태ful job의 작업 단위·체크포인트를 읽는 운영이 중요함을 보여준다. RHACS scanning HA도 CI의 보안 검사가 단일 장애점이 되지 않아야 함을 강조한다.

### Edge AI

GreenPipe와 로컬 Raspberry Pi 에이전트 신호가 잡혔다. 전력 예측과 로컬 실행 관심은 유지되지만, 장기 현장 운용과 독립 재현은 부족하다.

## 분야를 가로지르는 연결

평가 trace, rootless node, persistent session, stateful autoscaling은 모두 모델 출력보다 **실행 상태와 실패 경계**를 먼저 관리한다. 시드 글의 model–harness–environment 분리는 이번 주에 권한·복구·운영 신호를 가진 control plane으로 더 구체화됐다.

## 합의·충돌 주장

- **합의:** 운영형 에이전트에는 평가 자동화와 승인·복구 기록이 필요하다. Confidence: High.
- **합의:** Kubernetes 에이전트는 최소권한과 세션 소유권을 별도 정책으로 가져야 한다. Confidence: High.
- **충돌:** 여러 모델 조합이 비용을 줄인다는 공급자 평가는 독립 실사용 자료가 없다.
- **충돌:** 에이전트가 장애를 처리할수록 엔지니어 역량이 약해진다는 우려는 논의되지만 측정 근거가 부족하다.

## Kubernetes·Cloud·Edge 운영 영향

- rootless 전용 노드 풀에서 CNI·CSI와 privileged workload 호환성을 먼저 시험한다.
- agent task에 owner scope, durable session, tool effect idempotency와 재개 테스트를 넣는다.
- autoscaler는 CPU 외에 queue, checkpoint, cache와 CI critical path를 관측한다.
- edge 추론은 정확도와 함께 전력, throttling, 메모리 상한을 기록한다.
