## 분야별 핵심 변화

### Self-evolving harness

Living-Harness는 실행 경험을 persistent procedural repair로 만들고, AIDE²는 outer loop가 inner agent를 고정 비용 아래 평가한다. 공통점은 model이 마음대로 production을 다시 쓰게 하지 않고 외부 evaluator가 변경을 선별한다는 것이다. [[vault/Topics/Self-evolving harness|주제 노트]]

### AI agents

[[vault/Sources/Beyond Component Testing Validating Agentic AI Systems -- R001682|검증 survey]]와 [[vault/Sources/AgentSLABench Evaluating and Benchmarking Agentic Systems Under Resource Constraints -- R001673|AgentSLABench]]는 one-shot accuracy 밖의 시간·자원·multi-agent 경계를 평가 대상으로 끌어왔다. Agent 운영 대시보드는 최종 성공률만으로는 부족하다.

### Kubernetes·Cloud

[[vault/Sources/Multitenant AI inference with dynamic resource allocation on OpenShift -- R001700|DRA·MIG 예제]]는 scheduler-visible claim과 hardware partition을 연결했다. [[vault/Sources/Gateway API v1.6 TCPRoute and UDPRoute Graduate to Standard -- R001694|Gateway API v1.6]]은 L4 route를 정식 v1으로 올리고 experimental API를 별도 그룹으로 분리했다. [[vault/Sources/Agent Sandbox -- R001709|Agent Sandbox]]는 agent runtime을 stateful·isolated workload로 다루는 구현 기반이다.

### Edge

공식 자료와 검증 가능한 원문에서 큰 신규 architecture 전환은 확인되지 않았다. Local inference·cloud orchestration·fleet lifecycle을 workload별로 나누는 기존 원칙이 유지됐다.

## 분야를 가로지르는 연결

Harness의 evaluator gate, Kubernetes의 ResourceClaim, Gateway API의 Standard/Experimental 분리, sandbox의 permission boundary는 모두 같은 설계다. **AI가 바꿀 수 있는 상태를 명시하고, 변경을 외부 control plane이 검증·승격·복구한다.**

## 합의가 형성된 주장

- Agent 개선과 평가의 기본 단위는 isolated prompt가 아니라 장기 trajectory다. Confidence: Medium-High.
- Production agent에는 model 바깥의 permission·sandbox·audit·rollback 경계가 필요하다. Confidence: High.
- GPU multitenancy는 scheduler-visible resource model과 hardware isolation을 함께 써야 한다. Confidence: High.
- Edge/cloud 선택은 이념이 아니라 latency·privacy·connectivity·capacity 제약에 따른 placement다. Confidence: Medium-High.

## Kubernetes·Cloud·Edge 운영 영향

- DRA 도입 전 기존 NVIDIA device plugin과 자원 ownership 충돌을 점검한다.
- MIG profile, ResourceClaim, tenant namespace, network policy를 하나의 acceptance test로 묶는다.

- Agent sandbox에는 restore latency, idle suspension, egress, filesystem scope, kill switch를 별도 SLO로 둔다.
- Edge fleet는 model 배포뿐 아니라 OTA update, rollback, offline queue와 cloud reconciliation을 검증한다.
