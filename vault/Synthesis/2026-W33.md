## 지난 종합과 달라진 점

지난주에는 평가 gate, trajectory, Kubernetes DRA와 sandbox가 각각의 연구·운영 요소로 보였다. 이번 주에는 Cloudflare OS, Docker Sandboxes, Prime Agent처럼 이 요소를 실제 사용 가능한 플랫폼과 저장소로 묶는 사례가 나타났다. “왜 필요한가”에서 “어떤 제어면으로 구현하는가”로 논점이 이동했다.

## 분야별 핵심 변화

### Self-evolving harness

지속 상태, 실행 경험, evaluator가 공통 구조로 굳어지고 있다. Prime Agent는 long-running goal·heartbeat·schedule·subagent를 공개 구현으로 제공한다. 벤치마크 수치는 아직 독립 검증보다 빠르게 퍼지고 있다.

### AI agents

에이전트는 모델 호출기가 아니라 코드를 쓰고 외부 시스템을 만지는 장기 실행 주체로 취급된다. 따라서 권한, 상태 복구, 감사를 런타임 기능으로 넣는 흐름이 강해졌다.

### Kubernetes·Cloud

CNCF가 AI Inference + Agentic 전용 트랙을 추가했다. 이는 운영 관심의 공식화를 보여주지만 보급률의 증거는 아니다. [[vault/Sources/CNCF Reveals KubeCon + CloudNativeCon North America 2026 Schedule, Adds New AI Inference + Agent -- R001889|CNCF 발표]] · [원문](https://www.cncf.io/announcements/2026/08/10/cncf-reveals-kubecon-cloudnativecon-north-america-2026-schedule-adds-new-ai-inference-agentic-track/)

### Edge AI

Muse Glimmer는 로컬 agent workflow를 명시적으로 겨냥했다. 하지만 장치별 속도, 도구 사용 성공률, 배터리·메모리 비용은 독립 검증 전이다. Edge는 cloud 대체보다 workload placement 선택지로 보는 편이 안전하다.

## 분야를 가로지르는 연결

하네스의 persistent state, Cloudflare의 workspace, Docker의 sandbox, Kubernetes Agent Sandbox는 같은 문제를 다른 층에서 다룬다. 에이전트가 오래 살아남을수록 “어떤 상태를 보았고, 무엇을 쓸 수 있으며, 실패 후 어디서 복구하는가”가 공통 제어면이 된다.

## 합의가 형성된 주장

- 장기 실행 에이전트에는 최종 정답 외에 trajectory와 상태 변화 기록이 필요하다. Confidence: Medium-High.
- 실행 격리와 자격증명 중개는 모델 선택과 독립된 필수 계층이다. Confidence: High.
- 로컬과 클라우드는 대체 관계보다 지연시간·개인정보·용량에 따른 배치 문제다. Confidence: Medium.
- 보안 평가는 실제 도구 경계와 지속 메모리를 포함해야 한다. Confidence: Medium-High.

## 서로 충돌하는 주장

- Prime Agent와 Muse Glimmer의 공개 성능·비용 수치는 빠르게 공유되지만 독립 재현 자료는 부족하다.
- 샌드박스가 곧 안전이라는 홍보와 달리 기본 쓰기 마운트, egress, credential policy는 별도 검토가 필요하다.

## Kubernetes·Cloud·Edge 운영 영향

- 에이전트별 workspace의 쓰기 범위와 폐기 정책을 선언한다.
- 장기 API 키 대신 프록시·capability와 최소 권한을 사용한다.
- 복구 시간, idle 비용, 외부 통신, kill switch를 SLO로 둔다.
- 로컬 모델은 민감 데이터·오프라인 작업부터 제한적으로 검증한다.
- 도구 응답 오염과 persistent memory contamination을 배포 전 시험한다.
