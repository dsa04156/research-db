# 2026-08-25 오늘의 연구 브리핑

> **한 줄 결론:** AI 에이전트의 승부처가 모델 자체에서, 중단돼도 복구되고 상태와 권한을 통제하는 ‘하네스 실행 계층’으로 빠르게 이동하고 있다.

## 30초 요약

- Pi와 TrueForge가 하네스를 단순 도구 호출 루프가 아니라 세션·복구·승인·격리를 맡는 런타임으로 구체화했다.
- Kubernetes의 LLM 추론은 GPU 사용률만으로 라우팅할 수 없다. KV 캐시 위치와 대기 토큰까지 보는 추론 전용 스케줄러가 중요해졌다.
- 장기 에이전트 메모리에서는 압축으로 안전 규칙이 사라지거나, 한 번의 대화로 오염된 기억이 남는 문제가 새 연구 주제로 부상했다.
- Edge AI는 큰 제품 전환보다 열·통신량·장치 제약을 함께 다루는 운영 연구가 늘고 있다.

- **상승 — 하네스의 독립 런타임화.** 공식 설계·공개 구현과 HN·Threads 반응이 함께 확인됐다. Pi는 crash recovery와 operation log를, TrueForge는 sandbox·approval·session state와 Helm 배포를 전면에 둔다. Confidence: High.

- **유지 — 추론 상태를 읽는 Kubernetes 라우팅.** llm-d 공식 설명과 독립 아키텍처 해설이 KV/prefix cache와 queue-aware routing 필요성을 같이 지적한다. Confidence: High.
- **과열·미확정 — ‘자율 에이전트가 정부를 해킹했다’는 주장.** 단일 Reddit 게시 외에 독립된 정부·수사·보안 발표가 확인되지 않았다. Confidence: Low.

### 2. TrueForge 공개 하네스 — ✅ 확인된 사실

**무슨 소식?** 모델 호출, MCP 도구, skill, sandbox, 사람 승인, context와 session state를 하나의 실행 계층으로 제공한다. 로컬 SQLite부터 Postgres·Redis·Kubernetes Helm까지 배포 범위를 명시했다.

**왜 중요한가?** “하네스”가 개념어를 넘어 독립 배포 가능한 인프라 구성요소가 되고 있다는 두 번째 근거다. 성숙도와 대규모 운영 성능은 아직 별도 검증이 필요하다. [[vault/Sources/TrueForge open-source agent harness runtime -- R002285|Source]] · [원문](https://github.com/truefoundry/trueforge)

## 분야별 추가 동향

## 바로 써먹을 점

- agent 작업을 `accepted → effect intent → durable result → completed` 상태로 기록해 crash 지점을 재현한다.
- tool side effect는 operation ID로 멱등 처리하고, 재시작 뒤 중복 실행 여부를 판별한다.
- Kubernetes 추론 대시보드에 prefix-cache hit, queued tokens, prefill/decode 분포와 EPP 장애 상태를 추가한다.
- memory compaction에서 안전 규칙·비밀·일반 대화에 서로 다른 보존 정책을 적용한다.
