# 오늘의 연구 브리핑 — 2026-09-03

> **한 줄 결론:** 오늘은 모델보다 agent 실행 장치(harness)의 비용·권한·자동 확장 방식을 제대로 재는 일이 중요해졌다.

## 30초 요약

- Kubernetes v1.37은 HPA(수평 파드 자동 확장)의 0개 축소 기능을 Beta로 기본 활성화했다.
- GitHub와 Docker는 코딩 agent의 전체 작업 비용과 다중 harness 권한 통제를 운영 과제로 제시했다.
- 같은 모델도 harness에 따라 비용·성공률이 크게 달랐다는 자체 벤치마크가 나왔지만 독립 재현은 없다.
- Cloudflare workerd는 actor fetch 재시도와 tracing 개선을 포함한 릴리스를 냈다.
- arXiv는 timeout과 429로 오늘 논문에 누락 가능성이 있다.

## 트렌드 레이더

- **상승 — harness 비용 비교.** FrontierHarness는 같은 모델·런타임에서 작업당 중앙 비용이 $1.05~$18.34였다고 공개했다. HN·Reddit 반응도 있지만 자체 벤치마크다. **Confidence: Medium/Low** · [원문](https://frontierharness.org/)
- **유지 — 단계별 비용 관측.** 답변 길이보다 재시도·도구 호출·실패 단계까지 재자는 논점이 반복됐다. **Confidence: Medium** · [[vault/Sources/How we make AI coding more cost efficient without sacrificing task quality -- R002545|Source]]
- **유지 — 실행 권한 통제.** 모델과 harness가 바뀌어도 정책·승인 경계를 유지하자는 흐름이다. **Confidence: Medium** · [[vault/Sources/Below the Harness Governing a Multi-Model, Multi-Harness World -- R002546|Source]]

## 오늘 꼭 볼 것

### 1. HPA가 0개 파드까지 줄인다 — ✅ 확인된 사실

Kubernetes v1.37은 큐 길이 같은 외부 지표로 파드를 0개까지 줄였다가 다시 깨울 수 있다. 큐 소비자·배치·GPU 워커의 유휴 비용을 줄이지만, HTTP 요청에는 별도 버퍼가 필요하고 콜드 스타트가 생긴다. [[vault/Sources/Kubernetes v1.37 Scale Workloads to Zero with HorizontalPodAutoscaler -- R002542|Source]] · [원문](https://kubernetes.io/blog/2026/09/02/kubernetes-v1-37-hpa-scale-to-zero-beta/)

### 2. 코딩 agent 비용은 전체 작업으로 잰다 — ⚠️ 추가 검증 필요

GitHub는 전체 작업의 낭비와 재시도를 줄여야 한다고 설명했다. 완료 작업당 비용·성공률·재시도를 함께 재야 하지만 자체 사례라는 한계가 있다. [[vault/Sources/How we make AI coding more cost efficient without sacrificing task quality -- R002545|Source]] · [원문](https://github.blog/ai-and-ml/github-copilot/how-we-make-ai-coding-more-cost-efficient-without-sacrificing-task-quality/)

### 3. 다중 harness의 권한 경계 — ⚠️ 추가 검증 필요

Docker는 agent 권한을 실행 계층의 정책·승인으로 통제해야 한다고 주장했다. 이 경계는 프롬프트 밖에서 강제해야 한다. [[vault/Sources/Below the Harness Governing a Multi-Model, Multi-Harness World -- R002546|Source]] · [원문](https://www.docker.com/blog/below-the-harness-governing-a-multi-model-multi-harness-world/)

### 4. workerd 재시도·추적 개선 — ✅ 확인된 사실

replica actor fetch 재시도, 집계 수정, tracing span 리팩터링과 예외 기록이 포함됐다. 운영 효과의 크기는 아직 알 수 없다. [[vault/Sources/cloudflare workerd v1.20260903.1 -- R002550|Source]] · [원문](https://github.com/cloudflare/workerd/releases/tag/v1.20260903.1)

## SNS·커뮤니티 신호

- Reddit의 Kubernetes 장애분석 agent 사례는 read-only 진단과 수정 권한 경계를 강조했다. **lead_only**
- HN·Reddit의 harness 비용 논의는 독립 실험이 아니다.
- Threads 7개 질의는 유효 결과가 없었다. quick 조사는 Reddit·HN 중심이었다.
- arXiv는 4개 timeout, edge 질의 429로 **partial**이다.

## 바로 써먹을 점

- HPA 0축소는 durable queue가 있는 비동기 워커부터 시험한다.
- agent eval에 완료 작업당 비용·재시도·도구 호출·실패 단계를 넣는다.
- 운영 agent는 기본 read-only, 변경은 정책 엔진과 승인 뒤 실행한다.

## 아직 믿으면 안 되는 것

- FrontierHarness의 “17배”를 모든 작업에 일반화하면 안 된다.
- 성공 작업당 비용과 전체 작업당 비용은 다른 지표다.
- 단일 SNS 사례나 릴리스 목록만으로 운영 효과를 단정할 수 없다.
