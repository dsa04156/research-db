### ✅ GPU 공유 클러스터의 전체 그림

**무슨 소식?** CNCF 글은 GPU를 여러 팀이 나눠 쓰는 플랫폼에 DRA(동적 장치 할당), MIG, Kueue, vCluster, RDMA, DCGM exporter, OpenCost가 각각 어디에 들어가는지 제시한다.

**왜 중요한가?** GPU가 파드에서 보인다고 운영 준비가 끝난 것이 아니다. 토폴로지, 팀 격리, 장애 감지, 비용 배분을 함께 검증해야 한다. 글은 설계 안내이며 대규모 벤치마크는 아니다. [[vault/Sources/Building an AI factory on Kubernetes -- R002383|DB 노트]] · [원문](https://www.cncf.io/blog/2026/08/27/building-an-ai-factory-on-kubernetes/)

### ⚠️ Kubernetes 권한 최소화 자동화

**무슨 소식?** KubeCap 저자들은 프로젝트의 74.67%에 capability 설정이 없었고, 10개 Go 프로젝트에서 권한을 평균 54.97% 줄였다고 보고했다.

**왜 중요한가?** LLM의 자유 답변을 그대로 배포하지 않고 정적 분석과 결정적 출력으로 묶었다는 점이 실무적이다. 아직 작은 표본의 초기 논문이므로 수치보다 설계 패턴을 먼저 볼 만하다. [[vault/Sources/KubeCap A Framework for Capability Minimization in Kubernetes via Static Analysis and LLM-Assist -- R002380|DB 노트]] · [원문](https://arxiv.org/abs/2608.26699)

**왜 중요한가?** 엣지 장비를 공격자가 물리적으로 확보할 수 있다면 소프트웨어 격리만으로 모델 자산을 지키기 어렵다. 다만 Jetson이나 상용 NPU에서 재현된 결과는 아니다. [[vault/Sources/LLMscope Extracting LLM Assets from Edge AI Chips via Optical Probing -- R002386|DB 노트]] · [원문](https://arxiv.org/abs/2608.25321)
