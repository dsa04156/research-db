# 오늘의 연구 브리핑 — 2026-09-08

> **한 줄 결론:** 이번 주의 핵심은 더 강한 모델보다, 에이전트가 안전하게 실행·평가·복구되도록 하네스를 운영 계층으로 만드는 일이다.

## 30초 요약

- 에이전트의 운영 병목이 모델 성능에서 자동 평가, 실행 추적, 승인·복구 경계로 이동하고 있다.
- Kubernetes 1.37 rootless beta와 kagent 0.10.0이 최소권한·영속 세션·소유권 제어를 실제 기능으로 강화했다.
- Netflix Flink와 Red Hat 보안 스캔 사례는 자동화가 CPU뿐 아니라 작업 상태와 CI 경로를 읽어야 함을 보여준다.
- 신규 연구의 성능·비용 수치는 흥미롭지만 독립 재현 전이라 확정 사실로 쓰지 않았다.

- **상승 — 에이전트 평가·통제 하네스.** 발표, 사전논문, 독립 기술 분석의 3개 도메인이 같은 운영 병목을 지적한다. **Confidence: 높음**
- **상승 — Kubernetes 최소권한 에이전트.** Kubernetes 공식 문서와 kagent 릴리스가 비권한 실행, 세션 내구성, task 소유권을 구체화했다. **Confidence: 높음**
- **유지 — 서비스 상태 기반 자동화.** Flink autoscaler와 RHACS 고가용성 구조가 서로 다른 운영 계층에서 같은 방향을 보인다. **Confidence: 중간**
- **과열·미확정 — 에이전트 게시판·과설계 하니스 반작용.** 커뮤니티 관심은 크지만 발견기가 무관한 인기 영상을 합쳤다. **Confidence: 낮음**
- **유지 — 로컬·엣지 에이전트.** Raspberry Pi와 전력 모델링 신호는 있으나 독립 현장 검증이 부족하다. **Confidence: 낮음**

## 오늘 꼭 볼 것

### 1. 에이전트 운영의 진짜 병목은 평가다

**✅ 확인된 사실**  
**무슨 소식?** 자동 평가, 결함 분류, 실행 trace와 승인 경계를 제품 일부로 다뤄야 한다는 자료가 동시에 나왔다.  
**왜 중요한가?** 최종 답만 채점하면 왜 실패했는지, 재실행해도 안전한지 알 수 없다. 하네스가 평가·감사 계층을 가져야 한다.  
[[vault/Sources/Presentation From AI Agent Demo to Production Automated Testing and Evaluation -- R002663|Source]] · [원문](https://www.infoq.com/presentations/ai-agent-testing-evaluation/)

### 2. Kubernetes rootless node가 베타가 됐다

**✅ 확인된 사실**  
**무슨 소식?** kubelet과 런타임·네트워크 구성요소를 host의 비-root 사용자로 실행하는 기능이 Kubernetes 1.37 beta가 됐다.  
**왜 중요한가?** 컨테이너 탈출 시 host root까지 빼앗길 위험을 줄인다.  
**한계:** 커널 취약점은 막지 못하며 일부 CNI·CSI 호환성 검증이 필요하다.  
[[vault/Sources/Kubernetes v1.37 KubeletInUserNamespace (aka Rootless mode) Graduates to Beta -- R002631|Source]] · [원문](https://kubernetes.io/blog/2026/09/04/kubernetes-v1-37-rootless-beta/)

### 3. kagent가 세션과 소유권을 운영 기능으로 끌어올렸다

**✅ 확인된 사실**  
**무슨 소식?** kagent 0.10.0은 영속 세션 저장, A2A task store, owner-scoped 접근, 샌드박스 런타임과 guardrail을 확장했다.  
**왜 중요한가?** 장기 실행 에이전트를 재시작하고 공유할 때 필요한 상태·권한 경계가 제품 기능으로 내려왔다.  
[[vault/Sources/kagent-dev kagent v0.10.0 -- R002643|Source]] · [원문](https://github.com/kagent-dev/kagent/releases/tag/v0.10.0)

### 4. 상태ful 자동확장은 작업 의미를 읽어야 한다

**✅ 확인된 사실**  
**무슨 소식?** Netflix는 3만 개 이상 Flink job에 오픈소스 autoscaler 도입을 확대하고 있다. Red Hat은 보안 스캔 API가 CI의 단일 장애점이 되지 않는 HA 구조를 제시했다.  
**왜 중요한가?** CPU 사용률만 보지 말고 checkpoint, queue, scanner availability 같은 서비스 상태를 제어 신호로 써야 한다.  
[[vault/Sources/Netflix Moves Toward Open Source Flink Autoscaler for 30,000+ Streaming Jobs -- R002662|Flink Source]] · [원문](https://www.infoq.com/news/2026/09/netflix-flink-autoscaler/) / [[vault/Sources/Reference architecture for HA scanning with Red Hat Advanced Cluster Security for Kubernetes -- R002660|RHACS Source]]

### 5. 실행 제약과 학습 환경을 하네스 입력으로

**⚠️ 초기 연구·추가 검증 필요**  
**무슨 소식?** 자원 계약을 미리 주거나 환경 난이도를 진화시키면 에이전트 결과가 좋아진다는 두 사전논문이 나왔다.  
**왜 중요한가?** 하네스가 도구 목록뿐 아니라 시간·메모리·환경 난이도도 관리해야 한다는 방향을 제시한다. 수치는 독립 재현 전이다.

## 분야별 추가 동향

- **Self-evolving harness:** 평가 과정의 결함 유형과 ablation을 기록하는 거버넌스 연구가 추가됐다. 초기 연구다.
- **AI agents:** HydraFusion은 여러 모델을 선택적으로 조합한다. 공식 프리뷰지만 비용 효과는 공급자 자체 평가다.
- **Kubernetes:** rootless beta, kagent session·security, RHACS scanning HA가 권한과 복구 경계를 함께 강화한다.
- **Cloud/Distributed:** Flink 운영은 cluster 단위보다 job 단위 상태를 읽는 쪽으로 이동한다.
- **Edge AI:** GreenPipe가 K3s/Raspberry Pi 전력 예측을 제안했지만 제한된 실험이다.

## 바로 써먹을 점

- 에이전트 평가에 최종 답, tool trace, 승인 기록, 재시작 후 상태 복구를 함께 넣는다.
- rootless node는 별도 pool에서 CNI·CSI와 privileged workload 호환성을 먼저 시험한다.
- task·session 조회와 삭제를 owner scope로 제한하고 tool effect에 멱등 키를 둔다.
- autoscaler에 queue, checkpoint, cache, CI critical path를 서비스별 신호로 추가한다.
- edge 추론은 정확도와 함께 전력, 온도, throttling, 메모리 상한을 기록한다.
