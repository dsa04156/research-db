# 오늘의 AI 인프라 브리핑 - 2026-09-18

> **한 줄 결론:** 오늘은 더 강한 모델보다, 에이전트가 실패를 관찰하고 자원을 나누고 상태를 옮기며 실행 직전에 다시 확인하는 하네스가 중요해졌습니다.

## 30초 요약

- 에이전트 성능 차이는 모델뿐 아니라 도구 개선 루프와 작업별 자원 배치에서 크게 벌어지고 있습니다.
- 멀티 에이전트는 항상 정답이 아닙니다. 작업 단계가 촘촘히 연결될수록 단일 에이전트가 더 나을 수 있습니다.
- GLM 추론 인프라, 빠른 브라우저 에이전트, 에이전트 간 세션 이동이 오늘의 새 흐름으로 잡혔습니다.

## 오늘 꼭 볼 것

### 1. 도구를 스스로 고치는 영상 에이전트 `⚠️ 초기 연구·추가 검증 필요`

**무슨 소식?** VideoResearcher는 실패 기록을 보고 새 영상 분석 도구를 만들고 시험한 뒤 다음 작업에서 다시 씁니다. 모델 가중치는 바꾸지 않습니다.

**왜 중요한가?** 하네스 개선의 중심이 프롬프트 수정에서 실행 도구와 검증 루프로 이동합니다. 다만 저자 벤치마크 외의 재현은 더 필요합니다. [[vault/Sources/VideoResearcher Self-Improving Tool Design for Long-Video Understanding -- R002888|Source]] · [원문](https://arxiv.org/abs/2609.19664)

### 2. 에이전트마다 필요한 컴퓨팅 자원이 다르다 `⚠️ 초기 연구·추가 검증 필요`

**무슨 소식?** RAG, 웹 검색, 코딩 에이전트는 CPU·메모리·디스크 병목이 서로 달랐습니다. 저자들은 작업별 CPU 배치로 일부 지연을 크게 줄였다고 보고했습니다.

**왜 중요한가?** Kubernetes에서 모든 에이전트 Pod에 같은 자원 정책을 적용하면 낭비가 생길 수 있습니다. 수치는 단일 연구 환경 기준입니다. [[vault/Sources/Not All AI Agents Are Equal Characterizing Resource and Performance Dynamics -- R002893|Source]] · [원문](https://arxiv.org/abs/2609.19947)

### 3. 멀티 에이전트는 작업 구조를 보고 써야 한다 `⚠️ 초기 연구·추가 검증 필요`

**무슨 소식?** 새 연구는 느슨하게 나뉜 장기 작업에서는 여러 에이전트가 유리하지만, 순서 의존성이 강한 작업에서는 단일 에이전트가 낫다고 설명합니다.

**왜 중요한가?** 에이전트 수를 늘리기 전에 작업 그래프의 결합도와 컨텍스트 전달 비용부터 측정해야 합니다. [[vault/Sources/Rethinking Multi-Agent Collaboration When More Is Less -- R002887|Source]] · [원문](https://arxiv.org/abs/2609.19759)

### 4. OpenAI Agents SDK 운영 안정성 개선 `✅ 확인된 사실`

승인 인자 검증, 서버 재개, Windows 경로, 비동기 SQLite 시작 등 실패 경계가 수정됐습니다. 새 기능보다 재개·세션·샌드박스의 예측 가능성을 높인 릴리스입니다. [[vault/Sources/openai openai-agents-python v0.22.3 -- R002924|Source]] · [원문](https://github.com/openai/openai-agents-python/releases/tag/v0.22.3)

### 5. Karmada가 CNCF Graduation에 도달 `✅ 확인된 사실`

멀티클러스터 Kubernetes 프로젝트 Karmada가 CNCF 최고 성숙도 단계에 올랐습니다. 성능 우위 증명은 아니지만 장기 운영과 거버넌스의 신뢰 신호입니다. [[vault/Sources/Kubernetes Multi-Cluster Project Karmada Reaches CNCF Graduation -- R002922|Source]] · [원문](https://www.infoq.com/news/2026/09/karmada-kubernetes-cncf/)
