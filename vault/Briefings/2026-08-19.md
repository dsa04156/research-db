## 오늘 꼭 볼 것

### 1. ✅ 확인된 사실 — AgentRewind

**무슨 소식?** 에이전트 문맥과 제어 가능한 실행 환경을 같은 시점에 저장하고, 실패하면 이전 지점으로 돌아가 다시 실행한다.  
**왜 중요한가?** 긴 작업은 초반의 작은 실수가 파일·환경·후속 판단까지 오염시킨다. 앞으로는 재시도보다 ‘상태가 맞는 rollback’이 중요하다.  
**한계:** 외부 SaaS나 실제 장비에서 이미 일어난 부작용까지 자동으로 취소하는 것은 아니다.  
[[vault/Sources/AgentRewind Recoverable Execution for Long-Horizon LLM Agents -- R002084|Source]] · [원문](https://arxiv.org/abs/2608.14380v1)

### 2. ⚠️ 초기 연구·추가 검증 필요 — ClawGym II

**무슨 소식?** 하네스 실행을 직접 고치지 않고 모델 호출을 가로채 궤적을 복원한 뒤 PPO·GRPO 방식으로 학습한다.  
**왜 중요한가?** 서로 다른 하네스를 하나의 학습 파이프라인에서 다루는 길을 보여준다.  
**한계:** 프리프린트의 성능 수치는 독립 재현 전이다.  
[[vault/Sources/ClawGym II Exploring Black-Box RL on Agent Harness -- R002083|Source]] · [원문](https://arxiv.org/abs/2608.16798v1)

### 3. ⚠️ 초기 연구·추가 검증 필요 — OpScale와 GraniKV

**무슨 소식?** OpScale은 모델 내부 연산자 단위로 GPU를 배치·확장하고, GraniKV는 긴 공통 문맥과 개별 문맥의 KV-cache 저장 방식을 다르게 한다.  
**왜 중요한가?** multi-agent 비용과 지연을 줄이려면 replica 수만 조절해서는 부족하다는 뜻이다.  
**한계:** 최대 절감·처리량 수치는 각 논문의 하드웨어와 trace에 한정된다.  
[[vault/Sources/OpScale Operator-level Provisioning and Autoscaling for LLM Serving -- R002112|OpScale]] · [원문](https://arxiv.org/abs/2608.13499) · [[vault/Sources/GraniKV Asymmetric Granularity KV-Cache Paging for Multi-Agent Systems with Long Shared Prefix -- R002102|GraniKV]] · [원문](https://arxiv.org/abs/2608.15584v1)
