## 오늘 꼭 볼 것

### ✅ Kubernetes v1.37의 etcd RangeStream

**무슨 소식?** Kubernetes 공식 글에 따르면 `EtcdRangeStream`이 beta·기본 활성화됐다. etcd 3.7과 함께 큰 LIST 응답을 덩어리로 보내 API 서버와 etcd가 전체 결과를 동시에 메모리에 들고 있지 않게 한다.

**왜 중요한가?** Pod나 큰 객체가 많은 클러스터의 watch cache 초기화 때 메모리 급증과 OOM 위험을 줄일 수 있다. `etcd_request_duration_seconds_count{operation="listStream"}`가 0이 아닌지 확인해야 한다. [[vault/Sources/Kubernetes v1.37 etcd RangeStream Cuts Memory Use on Large List Reads -- R002520|DB 노트]] · [원문](https://kubernetes.io/blog/2026/09/01/kubernetes-v1-37-etcd-range-stream/)

### ⚠️ 모델에게 YAML을 직접 쓰게 하지 말라는 실험

**무슨 소식?** 한 GitOps 연구는 모델이 전체 파일이나 diff를 쓰게 하면 적용 실패나 조용한 주변 필드 변경이 생길 수 있다고 보고했다. 대신 리소스·필드·값만 구조화해 내보내고 결정적 편집기가 원문 한 지점만 바꾸는 방식을 제안한다.

**왜 중요한가?** 에이전트가 판단은 하되 실제 변경은 좁고 검증 가능한 프로그램이 맡는 구조다. 다만 오류율과 비용 수치는 단일 논문 결과다. [[vault/Sources/Don't Let the Model Write the YAML Deterministic, Minimal-Diff GitOps Remediation from LLM-Propo -- R002515|DB 노트]] · [원문](https://arxiv.org/abs/2609.00227)

### ✅ kagent v0.10.0-rc6

**무슨 소식?** 공식 RC 릴리스에 A2A 호출의 사용자 식별, 영속 저장소에서 정확한 task 읽기, OpenAI 임베딩 API 키 전달, CVE 수정 백포트가 포함됐다.

**왜 중요한가?** 여러 에이전트와 사용자가 섞인 Kubernetes 환경에서는 “누가 호출했는지”와 “어떤 task 상태를 읽었는지”가 권한·감사·재현성의 기본이다. RC이므로 운영 승격 전 회귀 시험이 필요하다. [[vault/Sources/kagent-dev kagent v0.10.0-rc6 -- R002525|DB 노트]] · [원문](https://github.com/kagent-dev/kagent/releases/tag/v0.10.0-rc6)

### ✅ Cloudflare workerd 런타임 안정성 수정

**무슨 소식?** 공식 릴리스는 hibernated WebSocket의 코드 업데이트 처리, actor fetch 재시도, Python Workers 플래그, 저장소 객체 수명 관련 수정을 묶었다.

**왜 중요한가?** 엣지·서버리스 에이전트는 모델보다 연결 유지와 재시도, 상태 수명 오류에서 더 자주 깨진다. [[vault/Sources/cloudflare workerd v1.20260902.1 -- R002526|DB 노트]] · [원문](https://github.com/cloudflare/workerd/releases/tag/v1.20260902.1)
