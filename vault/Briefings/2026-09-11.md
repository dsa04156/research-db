# 2026-09-11 오늘의 브리핑

> **한 줄 결론:** 백그라운드 에이전트가 늘면서 “끝날 때까지 지켜보는 채팅”보다 지속 상태·승인 대기열·검증 가능한 메모리·프로토콜 보안이 더 중요해지고 있다.

## 30초 요약

- Kubernetes가 실행 중 Pod의 증설이 막혔을 때 같은 노드의 저우선순위 Pod를 선점하는 Alpha 기능을 추가했다.
- AWS가 백그라운드 에이전트 작업을 메일함처럼 관리하는 오픈소스 Pizza Bot을 공개했다.
- 새 연구는 에이전트 메모리를 저장하기 전에 실제 환경을 읽기 전용으로 다시 확인하자고 제안한다.

## 오늘 꼭 볼 것

### 1. Pod 리사이즈를 위한 스케줄러 선점 — ✅ 확인된 사실

**무슨 소식?** 고우선순위 Pod의 인플레이스 리사이즈가 용량 부족으로 미뤄지면, 같은 노드의 저우선순위 Pod를 선점해 공간을 확보할 수 있다.

**왜 중요한가?** 추론 워크로드의 증설 대기를 줄일 수 있다. **한계:** Alpha·기본 비활성화이며 자동 확장과 함께 검증해야 한다. [[vault/Sources/Kubernetes v1.37 Scheduler Preemption for In-Place Pod Resize (Alpha) -- R002797|Source]] · [원문](https://kubernetes.io/blog/2026/09/10/kubernetes-v1-37-scheduler-preemption-for-in-place-pod-resize-alpha/)

### 2. Pizza Bot: 에이전트 작업을 메일함으로 — ✅ 확인된 사실

**무슨 소식?** 완료 작업은 Unread, 승인이 필요한 작업은 Action으로 보내며 실행 상태를 보존한다. 스케줄·웹훅·MCP·Agent Skills도 지원한다.

**왜 중요한가?** 오래 걸리는 작업을 비동기 업무 단위로 다룬다. **한계:** 커뮤니티 프로젝트라 AWS 지원과 SLA는 없다. [[vault/Sources/Introducing Pizza Bot, an open source inbox for AI agents that work in the background -- R002804|Source]] · [원문](https://aws.amazon.com/blogs/opensource/introducing-pizza-bot-an-open-source-inbox-for-ai-agents-that-work-in-the-background/)

### 3. 메모리를 저장하기 전에 환경을 다시 확인 — ⚠️ 초기 연구·추가 검증 필요

**무슨 소식?** 메모리 curator(정리 에이전트)에 최소 권한의 읽기 전용 도구를 줘 후보 기억이 현재 환경과 맞는지 확인한다.

**왜 중요한가?** 오류나 오래된 상태가 장기 기억으로 굳는 일을 줄일 수 있다. 성능·비용 개선은 독립 재현 전이다. [[vault/Sources/Grounding Agent Memory Environment-Probing Curation for Enterprise Agents -- R002789|Source]] · [원문](https://arxiv.org/abs/2609.11060)

### 4. A2A 명세의 보안 경계 — ⚠️ 초기 연구·추가 검증 필요

**무슨 소식?** A2ABreak는 A2A 명세를 상태 기계로 바꿔 분석하고, context ID 주입·위임 체인의 신원 손실·검증되지 않은 능력 광고 등 11개 취약점을 보고했다.

**왜 중요한가?** 구현 문제가 없어도 명세가 허용하는 흐름에서 공격이 생길 수 있다는 주장이다. 실제 구현별 재현이 필요하다. [[vault/Sources/A2ABreak Systematic Security Analysis of the A2A Protocol -- R002792|Source]] · [원문](https://arxiv.org/abs/2609.10871)

## 트렌드 레이더

- **상승 — 비동기 에이전트 작업함:** AWS 공식 공개와 독립 보도가 함께 확인됐다. 지속 실행·승인 대기·재접속 가능한 상태가 제품 구조의 중심이다. Confidence: High.
- **상승 — 에이전트 간 프로토콜 보안:** A2A 명세 분석과 커뮤니티의 신원·권한 논의가 동시에 보였다. 취약점 재현은 아직 단일 연구다. Confidence: Medium.
- **유지 — 도구 스키마를 필요할 때만 로드:** HN·Reddit에서 비용과 문맥 혼선을 줄이자는 논의가 반복됐지만 공식 벤치마크는 없다. Confidence: Low.

## 분야별 추가 동향

- **Self-evolving harness:** 비신뢰 입력과 실행 후 상태 확인이 반복됐다.
- **AI agents:** 공개 사고를 출처와 기전별로 기록하는 Agent Incident Registry가 제안됐다. 실제 실패율 자료는 아니다.
- **Kubernetes:** 재해 복구 시나리오와 리사이즈 선점이 함께 수집됐다.
- **Cloud/Distributed:** Pizza Bot은 로컬 서버와 체크포인트로 작업을 이어간다.
- **Edge AI:** 오늘 확인된 강한 공식 변화는 없었다. Threads 결과는 lead_only다.

## SNS·커뮤니티 신호

- HN·Reddit에서는 동적 도구 로딩, 로그인 실패, 사람 인계, 비신뢰 입력 처리가 반복됐다.
- Threads는 `edge ai` 일부 결과만 있었고 다른 6개 질의는 no-results였다.
- quick 모드는 Reddit·HN만 실질 확인됐다. 다른 플랫폼은 미확인이며 X는 제외했다.

## 바로 써먹을 점

- Pod 리사이즈 선점을 시험할 때 축출 횟수, 리사이즈 완료 시간, 자동 확장 충돌을 함께 측정한다.
- 백그라운드 에이전트 UI를 완료·대기·승인 필요 상태로 분리하고 재접속 후 복구를 테스트한다.
- 장기 기억 저장 전 읽기 전용 검증 단계와 출처·유효기간 필드를 둔다.
- A2A 위임에서 사용자 신원과 권한 범위 보존을 검사한다.

## 아직 믿으면 안 되는 것

- 메모리 논문의 성능·비용 수치를 모든 기업 환경에 일반화하면 안 된다.
- A2ABreak의 11개 항목이 모든 A2A 구현에서 곧바로 재현된다고 단정할 수 없다.
- 커뮤니티 반응량은 도구 스키마 최적화의 실제 절감률을 증명하지 않는다.
- Incident Registry 표본으로 에이전트의 실제 사고율을 계산하면 안 된다.
