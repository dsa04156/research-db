## 요약·초록

This document records a source-level review of the publicly available `google-ai-edge/LiteRT-LM` repository, conducted against two prior instruments: the Confidential Strategic Proposal transmitted by Green Recursive Utility Service LLC (GRUS) to nine Alphabet corporate channels on February 17, 2026, and United States Patent and Trademark Office Non-Provisional Utility Patent Application 19/700,381 (priority May 14, 2026), which specifies the Compressed Memory Manifold (CMM) data format. Fourteen source files were reviewed. Each is identified by path, and every observation reported below is independently verifiable by any party who clones the public repository. The review records what each file contains, what the assembled system describes when the files are read together, and — with equal weight — where lexical and structural-map constructs persist in that system. This document reports observations and states GRUS's position. It does not adjudicate that position. Adjudication rests with the tribunals and agencies before which the related matters are pending. --- ## 1. PURPOSE AND METHOD ### 1.1 What this review is A technical reading of public source code against a filed specification. Every file reviewed is recorded, including files bearing no correspondence. Ratings measure a file's contribution to the assembled architecture rather than its standalone significance, because no single source file contains a complete architecture: a loader shows loading, a cache shows caching, an offset shows offsetting. Correspondence is therefore assessed at the level of the assembled system. ### 1.2 What this review is not It is not a claim-chart, an infringement contention, or a legal conclusion. Those are instruments for a different forum and a different standard of proof. This document supplies the technical record on which such instruments would be built. ### 1.3 The governing test The CMM specification defines the protected subject matter by **enumerated absence** — the simultaneous omission of lexical delimiters and structural instruction maps from the stored representation. The specification is explicit that this classification does not depend on how a representation is produced or accessed: > §3.4 Implementation Independence — *"A CMM-format representation may be produced by any process... may be accessed by any retrieval method, including by fixed-offset arithmetic, AI inference, pattern matching, or future techniques. The format classification of the representation is unchanged by the selection of production method or retrieval method."* > §4.3 — *"The format itself, defined by enumerated absence, is independent of any specific implementation and is not limited by the performance characteristics of any single realization."* > §5 Scope of Protection — *"The patent application defines the protected subject matter by the comprehensive enumerated absence described in Section 2."* Accordingly, orchestration mechanics, runtime shape derivation, and the performance characteristics of any particular realization fall outside the classification test. The question is what is absent from the stored representation. --- ## 2.
