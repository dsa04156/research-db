### 1. [[vault/Sources/Prompt-Induced Waste in Large Reasoning Models A Preregistered Two-Harness Benchmark of Coding A -- R001729|두 하네스의 성공 비용 벤치마크]]

- 원문: [arXiv](https://arxiv.org/abs/2608.01347)
- **핵심 요약:** 6개 추론 모델, 2개 코딩 하네스, 24개 결정론적 과제, 4,643회 유효 실행을 비교했다. 같은 모델·과제·프롬프트라도 이 실험에서는 Claude Code의 성공당 비용이 pi보다 5~30배 높았다고 보고했다.
- **왜 중요한가:** 모델 단가만 비교하면 정적 프롬프트, 반복 turn, 중단 조건이 만드는 실제 낭비를 놓친다.
- **인프라·운영 영향:** 비용·token뿐 아니라 성공률을 결합한 `cost per success`, turn 수, 정적 prefix, 중단 사유를 하네스별로 측정해야 한다.
- **근거 수준과 Confidence:** ⚠️ 사전등록 arXiv preprint, Medium.
- **반증·한계:** 두 하네스와 제한된 코딩 과제의 결과다. 다른 버전·권한·도구 구성에 그대로 일반화할 수 없고 독립 재현도 아직 없다.

### 2. [[vault/Sources/LongHorizon-Harness Advancing Long-Horizon Agents for Real-World Tasks -- R001724|LongHorizon-Harness]]

- 원문: [arXiv](https://arxiv.org/abs/2608.01964)
- **핵심 요약:** 작업 상태를 긴 대화 안에 두지 않고 외부에 명시적으로 보관한다. Manager가 다음 작업을 정하고, fresh-context Executor가 실행하며, read-only Auditor가 환경 사실을 확인한 뒤에만 상태를 갱신한다.
- **왜 중요한가:** 장기 작업의 실패 원인을 모델의 추론력보다 상태 관리와 잘못된 자기완료 판정 문제로 재구성했다.
- **인프라·운영 영향:** 실행기·상태 저장소·검증기를 분리하고, 검증되지 않은 agent 서술이 durable state에 쓰이지 않게 해야 한다.
- **근거 수준과 Confidence:** ⚠️ 여러 benchmark의 저자 실험을 담은 preprint, Medium.
- **반증·한계:** Qwen·Claude의 개선 수치는 benchmark와 adapter 구성에 의존하며 production 장애 복구 성능은 공개되지 않았다.

### 3. [[vault/Sources/You can’t debug what you can’t see — Observability for AI Agents -- R001753|AI Agent 관측성]]

- 원문: [CNCF Blog](https://www.cncf.io/blog/2026/08/04/you-cant-debug-what-you-cant-see-observability-for-ai-agents/)
- **핵심 요약:** 일반 APM만으로는 agent가 같은 질문을 반복하거나 평소보다 큰 비용을 쓴 이유를 설명하기 어렵다. Agent 실행의 model call, tool call, 반복과 비용을 함께 봐야 한다는 현장 관점을 제시한다.
- **왜 중요한가:** Agent 문제는 HTTP 오류가 없어도 생긴다. 답은 나왔지만 경로가 비싸거나 잘못됐을 수 있다.
- **인프라·운영 영향:** 하나의 run ID에 prompt·model·tool·latency·token·cost·guardrail 결과를 연결하고 반복 loop를 경보 조건으로 둔다.
- **근거 수준과 Confidence:** ✅ CNCF 공식 기술 블로그의 production 경험, Medium-High.
- **반증·한계:** 표준이나 비교 실험이 아니라 운영 경험을 정리한 글이다.

### 4. [[vault/Sources/RoMeRL Balancing Feedback Coverage and the Memory-Reward Trap in Self-Evolving Agent Memory via -- R001734|RoMeRL]]

- 원문: [arXiv](https://arxiv.org/abs/2608.02508)
- **핵심 요약:** 계속 늘어나는 trajectory별 memory utility를 고정 차원의 상태로 줄여 피드백 희석과 잘못된 memory 보상을 완화한다. 저자들은 memory 크기 84.4% 감소, LLM call 21.1% 감소를 보고했다.
- **왜 중요한가:** 자기개선 memory가 커질수록 모든 경험을 보존하는 방식 자체가 학습 신호를 오염시킬 수 있음을 지적한다.
- **인프라·운영 영향:** Memory retention에 크기 제한, 교체 정책, 잘못된 memory의 격리·회수 지표를 둬야 한다.
- **근거 수준과 Confidence:** ⚠️ 이론과 두 benchmark를 포함한 preprint, Medium.
- **반증·한계:** 수치는 ALFWorld·LifelongAgentBench 조건의 저자 보고값이며 실제 장기 서비스 부하에서는 미검증이다.

### 5. [[vault/Sources/openai openai-agents-python v0.19.3 -- R001760|OpenAI Agents Python v0.19.3]]

- 원문: [GitHub Release](https://github.com/openai/openai-agents-python/releases/tag/v0.19.3)
- **핵심 요약:** tool 이름 충돌, resume 후 순서·중복 처리, guardrail 결과, session rollback, MCP pagination, streaming 종료·취소와 관련된 다수의 수정이 포함됐다.
- **왜 중요한가:** 실제 agent 장애가 모델 답변보다 재개·stream·session 경계에서 많이 발생한다는 운영 신호다.
- **인프라·운영 영향:** 업그레이드 전 interrupted stream, resumed tool call, guardrail trip, SQLite rollback을 회귀 테스트해야 한다.
- **근거 수준과 Confidence:** ✅ 공식 release, High.
- **반증·한계:** 변경량이 커서 모든 수정이 현재 사용 경로에 적용되는 것은 아니다.
