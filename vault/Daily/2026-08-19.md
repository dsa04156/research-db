## Codex 분석

### 오늘의 핵심 자료

1. [[vault/Sources/ClawGym II Exploring Black-Box RL on Agent Harness -- R002083|ClawGym II]] ([원문](https://arxiv.org/abs/2608.16798v1))
   - **검증 사실:** 복잡한 하네스를 블랙박스로 둔 채 모델 호출 경계에서 궤적을 복원하고 PPO·GRPO 학습을 적용하는 프리프린트다.
   - **왜 중요한가:** 하네스가 단순 실행기가 아니라 학습 대상과 평가 환경으로 이동하고 있음을 보여준다.
   - **운영 영향:** 대규모 rollout에는 임시 sandbox 격리, 학습-추론 일관성, 호출 추적이 필요하다.
   - **근거 수준:** A급 원문(저자 프리프린트), Confidence Medium. 독립 재현 전이며 논문 수치는 저자 보고다.

2. [[vault/Sources/AgentRewind Recoverable Execution for Long-Horizon LLM Agents -- R002084|AgentRewind]] ([원문](https://arxiv.org/abs/2608.14380v1))
   - **검증 사실:** 에이전트 문맥과 제어 가능한 환경을 함께 checkpoint해 이전 상태로 되돌리는 복구 런타임을 제안한다.
   - **왜 중요한가:** 장기 작업에서는 오류 예방만큼 실패 뒤 되돌리기와 재개가 핵심이라는 흐름을 강화한다.
   - **운영 영향:** 컨테이너·VM snapshot, 외부 부작용 보상, checkpoint 보존 비용을 함께 설계해야 한다.
   - **근거 수준:** A급 원문, Confidence Medium. 통제 밖 SaaS·실물 작업의 완전한 rollback은 보장되지 않는다.

3. [[vault/Sources/OpScale Operator-level Provisioning and Autoscaling for LLM Serving -- R002112|OpScale]] ([원문](https://arxiv.org/abs/2608.13499))
   - **검증 사실:** 모델 전체 대신 연산자 단위 탄력성을 활용하는 LLM serving provisioning·autoscaling 프레임워크다.
   - **왜 중요한가:** GPU autoscaling 단위를 더 잘게 쪼개 SLO와 비용을 동시에 다루려는 시스템 연구다.
   - **운영 영향:** 프로파일링·배치·런타임 routing 복잡성이 커지므로 Kubernetes 적용 시 스케줄러와 serving 계층의 공동 설계가 필요하다.
   - **근거 수준:** A급 원문, Confidence Medium. 최대 GPU·전력 절감 수치는 특정 trace와 하드웨어에서 얻은 저자 보고다.

4. [[vault/Sources/GraniKV Asymmetric Granularity KV-Cache Paging for Multi-Agent Systems with Long Shared Prefix -- R002102|GraniKV]] ([원문](https://arxiv.org/abs/2608.15584v1))
   - **검증 사실:** 다중 에이전트의 긴 공통 prefix와 요청별 suffix에 서로 다른 KV-cache paging granularity를 적용한다.
   - **왜 중요한가:** multi-agent serving 병목이 모델 계산만이 아니라 공유 문맥 저장·paging 구조에도 있음을 구체화한다.
   - **운영 영향:** prefix 재사용률, prompt 길이 분포, GPU 메모리 단편화를 별도 지표로 봐야 한다.
   - **근거 수준:** A급 원문, Confidence Medium. 1.57~2.16배 수치는 저자 환경의 결과이며 독립 재현이 필요하다.

5. [[vault/Sources/fx Tiny, open, embeddable, native coding agent -- R002125|fx]] ([원문](https://github.com/vercel-labs/fx))
   - **검증 사실:** Vercel Labs가 Zig 기반의 작고 임베드 가능한 모델 비종속 코딩 에이전트 하네스를 공개했다.
   - **왜 중요한가:** 무거운 범용 프레임워크와 반대로 작은 native harness를 제품 안에 넣으려는 방향이 HN·Reddit에서 함께 관찰됐다.
   - **운영 영향:** 작은 바이너리는 배포 표면을 줄일 수 있지만 permission·session·MCP 기능의 성숙도를 따로 검증해야 한다.
   - **근거 수준:** 공식 저장소 + 2개 커뮤니티, Confidence Medium. 프로젝트가 직접 experimental이라고 명시한다.

### 오늘 바뀐 지식

- 하네스 연구의 중심이 context 구성에서 **학습 가능한 실행 경계와 복구 가능한 상태**로 넓어졌다.
- GPU serving 최적화는 모델 단위 autoscaling을 넘어 operator와 KV-cache 배치 단위로 세분화되고 있다.
- 작은 native coding harness 관심은 확인됐지만, 생산 준비성 상승으로 해석할 근거는 아직 없다.

### 트렌드·약한 신호와 반증

- **상승 후보:** agent 도입이 승인·구성 복잡성을 늘린다는 반론이 HN·Reddit 양쪽에서 반복됐다. 다만 정량적인 생산성 저하 연구는 아니다.
- **과열·미확정:** MCP 대비 filesystem이 비용 27%, 지연 32%를 줄였다는 게시물은 원자료가 확인되지 않았고 자동 군집에 무관한 증거가 섞였다.
- **잘못된 귀속:** SNS가 [[vault/Sources/A Programming Paradigm for Spatiotemporal Composability -- R002127|Spatiotemporal Composability 프리프린트]]를 DeepSeek 논문이라고 불렀지만 공식 원문에서 DeepSeek 귀속을 확인하지 못했다.
- Threads는 harness engineering 관련 1건만 확인됐고 나머지 전용 질의는 no-results였다. 이는 플랫폼 전체에 논의가 없다는 뜻은 아니다.
