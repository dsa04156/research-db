## Codex 분석

### 오늘의 우선순위

1. **Kubernetes v1.37 RangeStream** — Kubernetes 공식 글이 etcd v3.7과 함께 대규모 LIST 읽기의 메모리 피크를 낮추는 스트리밍 경로가 beta·기본 활성화됐다고 설명한다. `listStream` 메트릭으로 실제 사용 여부를 확인할 수 있다.
2. **결정과 실행의 분리** — GitOps 논문은 모델이 YAML 전체나 diff를 직접 쓰게 하지 말고, 필드 변경 의도만 구조화해 내보낸 뒤 결정적 편집기가 적용해야 한다고 제안한다. 단일 논문 결과이므로 수치는 미확정이지만 설계 원칙은 하네스의 fail-closed 방향과 맞는다.
3. **하네스 변조·메모리 무효화** — 두 초기 논문은 자기개선 하네스가 평가·권한·출처 의무를 훼손할 수 있고, 오래된 복구 기억은 버전 계약으로 폐기해야 한다는 서로 보완적인 문제를 제기한다.
4. **kagent v0.10.0-rc6** — 공식 릴리스에는 A2A 호출의 사용자 식별, 영속 저장소의 정확한 task read, API 키 전달, CVE 백포트가 포함된다. RC이므로 운영 배포 전 회귀 검증이 필요하다.
5. **Cloudflare workerd** — 공식 릴리스는 hibernated WebSocket의 코드 업데이트, actor fetch 재시도, Python Workers 플래그와 저장소 수명 관련 수정을 포함한다.

- Kubernetes v1.37의 `EtcdRangeStream`은 beta이며 기본 활성화다. etcd 3.7 미만이면 기존 페이지 방식으로 자동 폴백한다.
- kagent 및 workerd 항목은 각 프로젝트의 공식 GitHub 릴리스다.
- CNCF 글 두 편은 관측성을 단순 지표 수집이 아닌 의미·문맥으로 확장하고, 플랫폼을 도구 모음이 아닌 정책화된 셀프서비스 인터페이스로 보라고 제안한다.

- 오늘 자료의 공통점은 모델이 인프라를 직접 수정하게 하기보다 **작은 의도, 결정적 적용, 관측 가능한 증거, 되돌리기**를 하네스의 기본 계약으로 만들라는 것이다.
- 시드 글의 자기진화 하네스는 성능뿐 아니라 평가·권한·기억 자체가 오염되지 않았는지 감시하는 별도 감사 계층이 필요하다.

### 미확정·반박 필요

- arXiv의 성능·비용 개선 수치는 저자 실험이며 독립 재현 전에는 일반화할 수 없다.
- Threads의 “샌드박스 평가만으로는 운영 엣지케이스를 못 잡는다”는 게시물은 방향성 신호일 뿐 단일 게시물이다.
- 트렌드 발견기의 ‘독립 2개 소스’ 표시는 서로 무관한 결과가 한 주제로 접힐 수 있어, 상승 확인 근거로 사용하지 않았다.
