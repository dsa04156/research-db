### 오늘의 핵심 자료

1. **[[vault/Sources/Building an AI factory on Kubernetes -- R002383|Building an AI factory on Kubernetes]]** · [원문](https://www.cncf.io/blog/2026/08/27/building-an-ai-factory-on-kubernetes/)
   - **핵심 요약:** CNCF Ambassador 글은 여러 팀이 하나의 GPU 풀에서 학습·추론·평가를 함께 수행하는 운영 스택을 제시한다. DRA·MIG·Kueue·KAI·Volcano, vCluster, RDMA, DCGM exporter, OpenCost 등을 단일 설계로 묶는다.
   - **인프라·운영 영향:** GPU를 단순히 파드에 붙이는 문제가 아니라 토폴로지, 테넌트 격리, 고속 네트워크, 장애 복구, 과금까지 함께 설계해야 한다. 특히 DCGM exporter는 GPU 상태와 사용량을 수집하는 관측 계층으로 명시돼 있다.
   - **근거 수준:** ✅ CNCF 공식 커뮤니티 기술 글(B). 구체적인 조합은 설계안이며 대규모 운영 성능을 독립 검증한 결과는 아니다. Confidence: High(내용), Medium(일반화).

2. **[[vault/Sources/KubeCap A Framework for Capability Minimization in Kubernetes via Static Analysis and LLM-Assist -- R002380|KubeCap]]** · [원문](https://arxiv.org/abs/2608.26699)
   - **핵심 요약:** Kubernetes 매니페스트와 컨테이너 진입점을 분석해 필요한 Linux capability만 추론하고 수정 매니페스트를 만든다. 저자들은 조사 프로젝트의 74.67%에 capability 설정이 없었고, Go 기반 10개 프로젝트에서 평균 54.97%를 줄였다고 보고한다.
   - **인프라·운영 영향:** LLM은 정책을 직접 집행하는 대신 커널 코드에서 규칙 후보를 만드는 보조 역할을 하고, 최종 결과는 정적 분석과 결정적 매니페스트로 남긴다. 보안 자동화에 적합한 패턴이다.
   - **근거 수준:** ⚠️ ISSRE 2026 채택 표기가 있는 저자 원문(A)이지만 v1 논문이며 표본이 작고 Go 중심이다. 독립 재현 전 수치를 일반화하면 안 된다. Confidence: Medium-High.

3. **[[vault/Sources/LLMscope Extracting LLM Assets from Edge AI Chips via Optical Probing -- R002386|LLMscope]]** · [원문](https://arxiv.org/abs/2608.25321)
   - **핵심 요약:** 저자들은 FPGA 기반 LLM 가속기에 레이저 전압 이미징을 적용해 임베딩, 어텐션, 양자화 가중치와 활성값을 복구했다고 보고한다.
   - **인프라·운영 영향:** 엣지 AI 보안 경계가 API·펌웨어·메모리 암호화만으로 끝나지 않는다. 고가 장비를 쓰는 물리 공격이지만, 반복 사용되는 버퍼와 계산 회로가 모델 자산 유출 표면이라는 점을 보여준다.
   - **근거 수준:** ⚠️ 저자 원문(A), 단일 FPGA 실험이다. 상용 Jetson·NPU로의 전이는 확인되지 않았다. Confidence: Medium.

### 오늘 바뀐 지식

- GPU 플랫폼 논의가 스케줄링 단일 기능에서 **테넌트 격리·토폴로지·관측·비용을 묶는 AI factory 운영 모델**로 확장됐다.

- 엣지 LLM 위협 모델에 **광학 물리 부채널을 통한 모델 자산 추출**을 추가해야 한다는 초기 증거가 생겼다.
- 하네스 커뮤니티에서는 컨텍스트·제약·정리와 결과 검증을 반복 가능한 운영 규칙으로 만드는 설명이 늘었다.
